CATEGORY 01

プロンプト設計の本質

概要

Claude Codeへの指示（プロンプト）は、「理想の状態」と「現状」のGAPを言語化したものに他ならない。このフレームを覚えれば誰でもプロンプトを書ける。

説明

プロンプト集やテクニック本に振り回される必要なし。「あなたは最高の○○です」式のロール指定もほぼ不要。やりたいこと（理想）と今の状態（現状）の差分を埋める文を書くだけ。

理想の状態

✅ こうなってほしい

→

GAP = プロンプト

📝 この差を言語化

←

現状

⚠️ 今こうなっている

メリット
  • プロンプト集を覚えなくていい
  • AIが何をすべきか明確になる
  • 最初の解像度が高いほど完成品の質が上がる
  • 修正ループ（出戻り）が減る
ポイント・観点
  • 理想を先に言語化する
  • 分からない時は AskUserQuestion でAIに聞かせる（→ ⑩）
  • アウトプット形式（HTML/CSV/ファイル名）を必ず指定
  • 「あなたは最高の○○です」は今は不要
具体的な指示文（ひいおばあちゃんの教え）
「タイトなリソースで
クイックなローンチを目指すため
バイブコーディングする
AIスタートアップでのベストプラクティスは
最初のプロンプトの時点での
スペックの解像度が重要よ...」

→ Claude Codeは1時間以上稼働することがある。「やり直し」のコストが従来比で激増。だから最初の解像度が決定的に重要。

やってみよう！チェックリスト
  • 今日やりたいことの「理想の状態」を一文で書く
  • 「現状」（今どうなっているか）を一文で書く
  • その差分（GAP）をプロンプトとして入力する
  • アウトプット形式（ファイル形式・命名規則）を指示に追加
  • 出来た結果を見て、解像度の不足箇所を振り返る

CATEGORY 02

Claude Code の基礎理解

概要

Claude CodeはPC内部に入り込んで直接ファイルを読み書き・実行するAI。ChatGPTのような「クラウド上で文章を返すだけ」ではない。

説明（4種類の使い方）
  • CLI版（ターミナル）：旧来のスタイル、上級者向け
  • Desktop版：今日のおすすめ、GUIで使いやすい
  • Web版：ほぼ使わない
  • IDE拡張：エディタ統合
他AIとの決定的な違い
ChatGPT / GeminiClaude Code
動く場所クラウドあなたのPC内部
ファイル操作テキスト返答のみ読む/書く/消すが直接可能
稼働時間都度応答長時間（1時間以上）連続作業
規模1ファイル単位大量ファイルを一括処理
📰 業界トピック
2026/4/25朝、Google → Anthropicへ300億ドル（約6.4兆円）の出資が報道。AI業界最大規模。
Desktop版でOK（ターミナル不要）

「Desktop版使ってんの？」と冷笑する人がいるかもしれないが、安心してDesktop版で問題ない。アップデートで機能差はほぼ解消。

やってみよう！チェックリスト
  • Claude Code Desktop をインストール
  • 「ローカル」を選択して動作させるフォルダを指定
  • 「クロード」「コワーク」「クロードコード」の3タブのうち一番右を選ぶ
  • Windowsの方は事前に Git をインストール

最も賢い・最も高い

バランス型

CATEGORY 04

権限・ファイルアクセスと安全性

概要

Claude CodeはPCの階層構造（ディレクトリ）の中で動く。動かす場所を決めずに広い権限を与えると、データを全消去するリスクすらある。

🚨 鉄則：ルートディレクトリには権限を与えない
必ず「中身のないテスト用フォルダ」から始める。データのある場所は権限を渡さない。
5つの権限モード
#モード挙動
1許可を確認毎回確認。安全だがめんどう
2編集を承認編集時のみ確認
3プランモード実行せず計画だけ提示
4自動モード限りなく自律的（おすすめ）
5許可をバイパス全自動、危険、初心者NG
講師の使い分け
大規模 → プランモードでまず計画確認 → 自動モードで実行
さくっと → 自動モード
設定方法（バイパス／自動を有効化）

左下 → 設定 → Claude Code → 「バイパス権限モードを許可」「自動権限モードを許可」をON。これを最初に有効化しないと選択肢に出ない。

やってみよう！チェックリスト
  • デスクトップに新しい空フォルダを作って動作場所に指定
  • 5つの権限モードを左下から確認
  • プランモードを試してClaudeに計画を出させる
  • バイパスモードは初心者のうちは絶対に使わない

# 処理対象

# 命名規則
ファイルリネーム（20枚すべて yyyymmdd_宛名_但し書き.jpg 形式に変換）

# Excel列定義
No. / 日付 / 宛名 / 金額(円) / 但し書き / 発行者 / ファイル名
命名規則のコツ：yyyymmdd 形式は世界共通で並び替えに強い。日本人にも見やすい鉄板フォーマット。

CATEGORY 08

MCP（外部サービス連携）

概要

MCP（Multi Context Protocol） はClaudeを外部サービス（Google Calendar, Gmail, Slack, Notion等）と接続する規格。AIをポケモンのように育てて技を増やすイメージ。

説明

MCPもAPIコネクターも、ニュアンスは「外部サービス接続用の道具」と捉えればOK。料理で言うと調味料（オイスターソースを買い足すと料理の幅が広がる）。

メリット
  • カレンダーから空き時間を抽出してメール下書きまで自動化
  • 名刺Excel × Gmail MCP で営業メールの下書きを20件一気に生成
  • 自社業務システムとの連携で日常業務を自動化
設定手順
  1. 左下 → 設定 → コネクター
  2. Google Calendar / Gmail / Slack / Notion などから接続
  3. OAuthでログイン → 許可
  4. チャットから自然言語で利用開始
⚠ 安全運用
メール送信MCPは「下書きまで」に止める。最終送信は人間がやる。情報漏洩リスクのある業務は基本やらない。
指示文の例
Googleカレンダーと連携して1週間分の予定を教えてください。
および1時間のZoom会議ができる空き時間を教えてください。
# フル統合の例（今日やったこと全部のせ）
名刺Excelをもとに、Gmail MCPを使って全員分のメールを作りたい。
それぞれの会社名や役職から事業内容を予想して、
道草株式会社のAI研修を販売する文言を書いて、
20件分の下書きをGmailに入れておいてください。
やってみよう！チェックリスト
  • 設定 → コネクター から Google Calendar を接続
  • 「今週の予定を教えて」と聞いてみる
  • Gmail MCPで「下書き」生成を試す（送信はしない）
  • 自分が連携したい外部サービスをリスト化

CATEGORY 10

AskUserQuestionツール（要件定義をAIに聞かせる）

概要

「タスク管理システムを作って」と言われても、そもそも理想像が分からないのが普通。AskUserQuestionツールはClaudeから質問させて要件を引き出す機能。

なぜ必要か

Claudeは1回の指示で1時間以上稼働しうる。最初の解像度が低いと大規模な出戻りが発生する。質問を通じて理想を言語化させることで損失を回避。

具体的な指示文（魔法のフレーズ）
タスク管理システムを作りたい。
AskUserQuestionToolsを使って、まずは質問してくれ

→ Claudeが「Webアプリ？ネイティブ？」「ログイン機能必要？」「カテゴリ管理は？」「リマインダー要る？」など段階的に聞いてくれる。

代替案（節約派向け）

Claudeのトークンを節約したいなら、ChatGPTやGeminiで先に要件定義の壁打ちを済ませてから、固まった要件をClaude Codeに渡す。

タスク管理システムを作りたいんだけど、要件定義のために
どんな場面で使うか、機能は何が必要か質問してくれない？
やってみよう！チェックリスト
  • 「○○を作りたい。AskUserQuestionToolsを使って質問してくれ」と入力
  • Claudeの質問に1問ずつ答える
  • 出来上がりが指示なしの場合とどう違うか比較
  • ChatGPT/Geminiでの要件壁打ちも試す

CATEGORY 12

Desktop版おすすめコマンド

概要 & メリット

Desktop版にはセッション管理・コンテキスト確認用のスラッシュコマンドが用意されている。これだけで日常運用が劇的に楽になる。

3つのコマンド
/resume セッションを再開。左サイドバーから過去セッション一覧を見て続きから作業
/context 作業量（コンテキスト使用量）を確認。右下に常時表示されている
/clear 新しく始めたい時。または「New Session」ボタンで開始
コンテキストの上限：200K規模。これを超えるとAIが過去の指示を忘れる。長時間作業ではこまめにチェック。
やってみよう！チェックリスト
  • /resume で過去セッション一覧を表示
  • /context でコンテキスト使用量を確認
  • 右下のインジケーターを常に意識
  • /clear で新規セッションを切る癖をつける

CATEGORY 13

音声入力

概要

長文プロンプトはタイピングより音声入力が圧倒的に速い（タイピング全国12位の講師でも音声の方が速い）。機械に話しかける感覚に慣れることが重要。

メリット
  • タイピング速度の上限を超える
  • 思考をそのまま言語化できる
  • 長い理想像の言語化が苦にならない
おすすめソフト
ソフト評価備考
Aqua Voice推奨安定性で一番おすすめ
OS標準手軽Win+H / Mac Fn×2
Typeless候補差分は大きくない
Voice OS候補差分は大きくない
甲乙つけ難いが、安定性でAqua Voiceが最推し。まずOS標準で試して、物足りなければAqua Voiceへ。
ガジェット

パソコン内蔵マイクは音質が落ちる。外付けマイクが1個あると入力精度が向上。本気でやるならShure等の高音質マイク。

やってみよう！チェックリスト
  • OS標準音声入力をまず試す
  • Aqua Voiceをインストールして試す
  • 普段のプロンプトを声で入力してみる
  • 「機械に話しかける」感覚に慣れる練習を1日10分

🎤 【講師側ポイント】伝え方・見せ方の技術

このセミナーで使われていた「刺さる伝え方」のテクニック集。
自分が講師としてセミナーをやる時にそのまま真似できる構造に分解した。

🚀 技①｜インパクトファースト（すごいことを先に見せる）

📺 セミナーでやっていた具体例

講師は途中で 「Notionクローン」「Slackクローン」 を実際に作って見せ、「もうNotionじゃないですか」「もうSlackですね」と言いながら動作デモを行う。

🎯 なぜ効くか

「言葉で説明される前に目で見た」ものは強く印象に残る。難しい概念より先に「すごいアウトプット」を体験させると、「自分もやってみたい」という強い動機が生まれる。

💡 自分のセミナーへの応用
  • 冒頭または各章の頭で「最終ゴール完成物」をデモする
  • 受講者が「えっ、これ作れるの？」と驚く題材を選ぶ
  • 難しさより「インパクト」を優先（Notion/Slackクローンが鉄板）

👵 技②｜身近な例 → 専門用語の落差で刺す

📺 セミナーでやっていた具体例

「ひいおばあちゃんが病院で最後に教えてくれた言葉」として、誰もがわかる身近なイメージを出した直後に、専門用語だらけの一文を見せる。

「タイトなリソースで
クイックなローンチを目指すため
バイブコーディングする
AIスタートアップでのベストプラクティスは
最初のプロンプトの時点での
スペックの解像度が重要よ...」
🎯 なぜ効くか

親しみやすいエピソードから難しい概念への「落差」が笑いと「なるほど」を同時に生む。記憶への定着率が圧倒的に上がる。

💡 自分のセミナーへの応用
  • 重要概念は身近な例え話 → 専門表現の順で出す
  • 「おばあちゃんに説明するなら？」を一段挟む
  • 落差ギャップを意図的に作って笑い+理解を両立

📊 技③｜核心を1枚のフレームで伝える

📺 セミナーでやっていた具体例

💡 自分のセミナーへの応用

  • 「来週の月曜日、誰かに教えてみてください」と宿題化

⚡ 技⑥｜進行は早く、躓きはAIで自走させる

📺 セミナーでやっていた具体例

💡 自分のセミナーへの応用
  • 進行ルールを冒頭で明示してペースの主導権を握る
  • 録画提供を約束して「今ここで質問しなくていい」と安心させる
  • エラーは「100%出ます」と先に言って心理的負担を下げる
